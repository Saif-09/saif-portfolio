## ಸಮಸ್ಯೆ

ಆನ್‌ಲೈನ್ ಶಾಪಿಂಗ್ ಒಂದು ಬ್ರೌಸಿಂಗ್ ಸಮಸ್ಯೆಯಂತೆ ನಟಿಸುವ ಹುಡುಕಾಟದ ಸಮಸ್ಯೆಯಾಗಿದೆ. ಜನರಿಗೆ ತಾವು ಏನು ಬೇಕು ಎಂದು ಅಂದಾಜು ಗೊತ್ತಿರುತ್ತದೆ, ಉದಾಹರಣೆಗೆ "ಲಿನನ್ ಶರ್ಟ್, ಬಾಕ್ಸಿ ಅಲ್ಲ, 2k ಒಳಗೆ", ಆದರೆ ಅಂಗಡಿಗಳು ಆ ಉದ್ದೇಶವನ್ನು ಫಿಲ್ಟರ್‌ಗಳು, ವರ್ಗಗಳು ಮತ್ತು ಅದೃಷ್ಟದ ಮೂಲಕ ಭಾಷಾಂತರಿಸುವಂತೆ ಮಾಡುತ್ತವೆ. Shoppin' ಈ ಅಂತರವನ್ನು ಮುಚ್ಚಲು ಅಸ್ತಿತ್ವದಲ್ಲಿದೆ: ಜನರು ತಾವು ಯೋಚಿಸುವ ರೀತಿಯಲ್ಲಿ ಶಾಪಿಂಗ್ ಮಾಡಲು ಅವಕಾಶ ನೀಡುವುದು, AI ಭಾಷಾಂತರವನ್ನು ಮಾಡುತ್ತದೆ.

ನಾನು ಉತ್ಪನ್ನ ತಂಡದ ಭಾಗವಾಗಿ ಇದರ ಮೇಲೆ ಕೆಲಸ ಮಾಡುತ್ತೇನೆ. ನನ್ನ ಕೆಲಸವೆಂದರೆ ಅದು ಇರುವ ಎಲ್ಲಾ ಪ್ಲಾಟ್‌ಫಾರ್ಮ್‌ಗಳಲ್ಲಿ ಉತ್ಪನ್ನ ಎಂಜಿನಿಯರಿಂಗ್ ಮಾಡುವುದು: iOS ಮತ್ತು Android ಅಪ್ಲಿಕೇಶನ್‌ಗಳು, ವೆಬ್ ಅನುಭವ, ಮತ್ತು ಅವುಗಳ ಹಿಂದಿರುವ Node ಮತ್ತು Python ಬ್ಯಾಕೆಂಡ್‌ಗಳು, ಉತ್ಪನ್ನವು ಇನ್ನೂ ತನ್ನ ಆಕಾರವನ್ನು ಕಂಡುಕೊಳ್ಳುತ್ತಿರುವಾಗ.

## ಪಾತ್ರ

ನಾನು ಇಲ್ಲಿ ಉತ್ಪನ್ನ ಎಂಜಿನಿಯರ್ ಆಗಿ ಕೆಲಸ ಮಾಡುತ್ತೇನೆ, ಮತ್ತು ಕೋಡ್ ಆ ಕೆಲಸದ ಸಣ್ಣ ಭಾಗವಾಗಿದೆ. ನಾನು ಏನನ್ನಾದರೂ ನಿರ್ಮಿಸುವ ಮೊದಲು, ಆ ವೈಶಿಷ್ಟ್ಯವು ಬಳಕೆದಾರರ ಭಾವನೆಗಳನ್ನು ಹೇಗೆ ಬದಲಾಯಿಸುತ್ತದೆ ಮತ್ತು ಅದು ನಿಜವಾಗಿಯೂ ಉತ್ಪನ್ನವನ್ನು ಮುಂದಕ್ಕೆ ಕೊಂಡೊಯ್ಯುತ್ತದೆಯೇ ಎಂದು ತಿಳಿಯಲು ಬಯಸುತ್ತೇನೆ. ಅಂದರೆ, ಕೇವಲ ಟಿಕೆಟ್‌ಗಳಲ್ಲದೆ, ಉತ್ಪನ್ನ ಮತ್ತು ವಿನ್ಯಾಸದ ನಿರ್ಧಾರಗಳಿಗೆ ಹತ್ತಿರವಾಗಿರುವುದು: PostHog ನಲ್ಲಿ ಬಳಕೆದಾರರ ನಡವಳಿಕೆಯನ್ನು ಓದುವುದು, WebEngage ಮೂಲಕ ಲೈಫ್‌ಸೈಕಲ್ ಮತ್ತು ಮರು-ನಿಶ್ಚಿತಾರ್ಥದ ಹರಿವುಗಳನ್ನು ನಡೆಸುವುದು, ಮತ್ತು ವೆಬ್ ಮೇಲ್ಮೈಯನ್ನು ಸುಲಭವಾಗಿ ಹುಡುಕಲು Google Search Console ಅನ್ನು ಗಮನಿಸುವುದು. ಸ್ವಚ್ಛವಾಗಿ ಬಿಡುಗಡೆಯಾದ ಆದರೆ ಯಾರೂ ಅಳವಡಿಸಿಕೊಳ್ಳದ ವೈಶಿಷ್ಟ್ಯವು ನಾನು ಅಳೆಯಬಹುದಾದ ವೈಫಲ್ಯವಾಗಿದೆ, ಆದ್ದರಿಂದ ನಾನು ಅಳವಡಿಕೆ ಮತ್ತು ಉಳಿಸಿಕೊಳ್ಳುವಿಕೆಯನ್ನು ನನ್ನ 'ಮುಗಿದಿದೆ' ಎಂಬ ವ್ಯಾಖ್ಯಾನದ ಭಾಗವಾಗಿ ಪರಿಗಣಿಸುತ್ತೇನೆ, ಬೇರೆಯವರ ಸಮಸ್ಯೆಯಾಗಿ ಅಲ್ಲ.

## ನಾನು ಯಾವುದರ ಮೇಲೆ ಕೆಲಸ ಮಾಡುತ್ತೇನೆ

**ಅನಂತ ಶೆಲ್ಫ್ ಹೊಂದಿರುವ ರಚಿತವಾದ ಕ್ಯಾಟಲಾಗ್.** ಕಳೆದ ಮೂರು ತಿಂಗಳಿಂದ ತಂಡವು Shoppin' ನ ಇ-ಕಾಮರ್ಸ್ ಭಾಗವನ್ನು ನಿರ್ಮಿಸುತ್ತಿದೆ, ಮತ್ತು ಇದು ಸಾಮಾನ್ಯ ಮಾದರಿಯನ್ನು ಮುರಿಯುತ್ತದೆ: ಜನರು ಖರೀದಿಸುವ ಬಟ್ಟೆಗಳು ಎಂದಿಗೂ ಗೋದಾಮಿನಲ್ಲಿ ಇರಲಿಲ್ಲ. ಅಪ್ಲಿಕೇಶನ್ ಮತ್ತು ಸೈಟ್‌ನಲ್ಲಿ ತೋರಿಸಿರುವ ತುಣುಕುಗಳು AI ನಿಂದ ರಚಿಸಲ್ಪಟ್ಟಿವೆ ಅಥವಾ ಮೂಲದಿಂದ ಪಡೆದವು, ನಂತರ ಪಟ್ಟಿಮಾಡಲಾಗಿದೆ, ಆದ್ದರಿಂದ ಶೆಲ್ಫ್ ಪರಿಣಾಮಕಾರಿಯಾಗಿ ಅನಿಯಮಿತವಾಗಿದೆ ಮತ್ತು ಪ್ರತಿ ಉಡುಪನ್ನು ಒಬ್ಬ ವ್ಯಕ್ತಿಗಾಗಿ ಆರ್ಡರ್‌ಗೆ ಅನುಗುಣವಾಗಿ ತಯಾರಿಸಲಾಗುತ್ತದೆ. ದಾಸ್ತಾನು ಇಲ್ಲ ಎಂದರೆ ಸ್ಟಾಕ್‌ಔಟ್‌ಗಳಿಲ್ಲ ಮತ್ತು ಡೆಡ್ ಸ್ಟಾಕ್ ಇಲ್ಲ, ಆದರೆ ಯಾರಾದರೂ ಅದನ್ನು ಕೇಳುವವರೆಗೆ ಏನೂ ಅಸ್ತಿತ್ವದಲ್ಲಿಲ್ಲ ಎಂದು ಆರ್ಡರ್ ಮತ್ತು ಪೂರೈಕೆ ಊಹಿಸಬೇಕು ಎಂದರ್ಥ. ನಾನು ಆ ಸಂಪೂರ್ಣ ಮಾರ್ಗದಲ್ಲಿ ಕೆಲಸ ಮಾಡುತ್ತೇನೆ: ವೆಬ್ ಸ್ಟೋರ್, ಅಪ್ಲಿಕೇಶನ್, Node ವಾಣಿಜ್ಯ ಬ್ಯಾಕೆಂಡ್, ಮತ್ತು ಉತ್ಪಾದನೆ ಮತ್ತು AI ಕೆಲಸದ ಹಿಂದಿರುವ Python ಸೇವೆಗಳು.

**ಉಡುಪನ್ನು ಸಂಪಾದಿಸುವ ಚಾಟ್.** ನಾನು ಹೊಂದಿರುವ ವೈಶಿಷ್ಟ್ಯಗಳಲ್ಲಿ ಒಂದು ಬಳಕೆದಾರರಿಗೆ AI ಜೊತೆ ಮಾತನಾಡಲು ಮತ್ತು ಬಟ್ಟೆಯನ್ನೇ ಬದಲಾಯಿಸಲು ಅವಕಾಶ ನೀಡುತ್ತದೆ, ಅವರು ಬಯಸಿದ ವಸ್ತುವಾಗುವವರೆಗೆ ಅದನ್ನು ಸರಿಹೊಂದಿಸುತ್ತದೆ. ಮೊದಲ ಆವೃತ್ತಿಯು ಕೆಲಸ ಮಾಡಿತು ಆದರೆ ನಿಧಾನ ಮತ್ತು ಅಸಮಂಜಸವಾಗಿತ್ತು, ಆದ್ದರಿಂದ ಪ್ರತಿಕ್ರಿಯೆಗಳು ವೇಗವಾಗಿ ಮತ್ತು ವಿಶ್ವಾಸಾರ್ಹವಾಗಿ ಗುರಿಯನ್ನು ತಲುಪುವವರೆಗೆ ನಾನು ಪೈಪ್‌ಲೈನ್ ಮತ್ತು ಪ್ರಾಂಪ್ಟಿಂಗ್ ಅನ್ನು ಉತ್ತಮಗೊಳಿಸಿದೆ. ಇದು ಉತ್ಪನ್ನದ ಮಾಂತ್ರಿಕ ಭಾಗದಂತೆ ಭಾಸವಾಗುತ್ತದೆ, ಆದ್ದರಿಂದ ಅದು ಪ್ರಯತ್ನವಿಲ್ಲದಂತೆ ಭಾಸವಾಗಬೇಕು.

**ಪಾವತಿಗಳು, ಜನರು ಪಾವತಿಸುವ ಎಲ್ಲೆಡೆ.** ನಾನು ಪಾವತಿ ಪದರವನ್ನು ಸಂಪೂರ್ಣವಾಗಿ ನಿರ್ಮಿಸಿದೆ: ಭಾರತಕ್ಕಾಗಿ Razorpay, ಅಂತರರಾಷ್ಟ್ರೀಯಕ್ಕಾಗಿ Stripe, ಮತ್ತು ಅಪ್ಲಿಕೇಶನ್‌ನಲ್ಲಿ ಸ್ಥಳೀಯ Apple Pay ಮತ್ತು Google Pay, ಇದರಿಂದ ಚೆಕ್‌ಔಟ್ ಜನರು ತಮ್ಮ ಸಾಧನದಲ್ಲಿ ಈಗಾಗಲೇ ನಂಬಿರುವ ಪಾವತಿ ವಿಧಾನವನ್ನು ಬಳಸುತ್ತದೆ. ವಸ್ತುವನ್ನು ಬಯಸುವುದಕ್ಕೂ ಮತ್ತು ಅದನ್ನು ಹೊಂದುವುದಕ್ಕೂ ನಡುವೆ ಕಡಿಮೆ ಟ್ಯಾಪ್‌ಗಳು.

**ಎರಡೂ ಪ್ಲಾಟ್‌ಫಾರ್ಮ್‌ಗಳಲ್ಲಿ ಕಾರ್ಯನಿರ್ವಹಿಸುವ ಚಂದಾದಾರಿಕೆಗಳು.** ನಾನು ಚಂದಾದಾರಿಕೆ ವ್ಯವಸ್ಥೆಯನ್ನು Qonversion ನೊಂದಿಗೆ ಸಂಯೋಜಿಸಿದೆ, ಇದರಿಂದ ಮರುಕಳಿಸುವ ಯೋಜನೆಗಳು iOS ಮತ್ತು Android ಎರಡರಲ್ಲೂ ಸ್ಥಿರವಾಗಿ ವರ್ತಿಸುತ್ತವೆ, ಪ್ರತಿ ಪ್ಲಾಟ್‌ಫಾರ್ಮ್‌ಗೆ ರಸೀದಿ ಮೌಲ್ಯೀಕರಣ ಮತ್ತು ಹಕ್ಕುಗಳ ತರ್ಕವನ್ನು ಕೈಯಾರೆ ಬರೆಯುವ ಅಗತ್ಯವಿಲ್ಲ. ಖರೀದಿ ಸ್ಥಿತಿ ಮತ್ತು ಪ್ರವೇಶ ಒಂದೇ ಸ್ಥಳದಲ್ಲಿ ಇರುತ್ತದೆ, ಇದು ಚಂದಾದಾರಿಕೆ ದೋಷಗಳು ಅಡಗಿಕೊಳ್ಳುವ ಸ್ಥಳವಾಗಿದೆ.

**WhatsApp ನಲ್ಲಿ ಆರ್ಡರ್ ಅಪ್‌ಡೇಟ್‌ಗಳು.** ಯಾರಾದರೂ ಆರ್ಡರ್ ಮಾಡಿದಾಗ, ಏನಾಗುತ್ತಿದೆ ಎಂದು ತಿಳಿಯಲು ಅವರು ಅಪ್ಲಿಕೇಶನ್‌ಗೆ ಹಿಂತಿರುಗಬೇಕಾಗಿಲ್ಲ. ಪ್ರತಿ ಆರ್ಡರ್ ಅಪ್‌ಡೇಟ್ ಅನ್ನು WhatsApp ಮೂಲಕ ಗ್ರಾಹಕರಿಗೆ ತಲುಪಿಸುವ ಹರಿವನ್ನು ನಾನು ನಿರ್ಮಿಸಿದೆ, ಇದರಿಂದ ಪ್ರತಿ ಸ್ಥಿತಿ ಬದಲಾವಣೆಯು ಅವರು ಈಗಾಗಲೇ ಇರುವ ಸ್ಥಳದಲ್ಲಿ ಅವರನ್ನು ತಲುಪುತ್ತದೆ.

**ಆರ್ಡರ್‌ಗಳನ್ನು ನಿರ್ವಹಿಸಲು ಡ್ಯಾಶ್‌ಬೋರ್ಡ್.** ಆರ್ಡರ್‌ಗಳನ್ನು ನಿರ್ವಹಿಸಲು ಒಂದು ಸ್ಥಳ ಬೇಕು, ಆದ್ದರಿಂದ ತಂಡವು ಆರ್ಡರ್‌ಗಳನ್ನು ನೋಡಲು ಮತ್ತು ಅವುಗಳ ಲೈಫ್‌ಸೈಕಲ್ ಮೂಲಕ ಸರಿಸಲು ಬಳಸುವ ಆಂತರಿಕ ಡ್ಯಾಶ್‌ಬೋರ್ಡ್ ಅನ್ನು ನಾನು ನಿರ್ಮಿಸಿದೆ. ಗ್ರಾಹಕ-ಮುಖಿ ಉತ್ಪನ್ನವು ಅದರ ಹಿಂದಿರುವ ಕಾರ್ಯಾಚರಣೆಗಳಷ್ಟೇ ಉತ್ತಮವಾಗಿರುತ್ತದೆ.

**ಎರಡು ಬ್ಯಾಕೆಂಡ್‌ಗಳು, ಒಂದು ಉತ್ಪನ್ನ.** Node.js ವಾಣಿಜ್ಯ ಮತ್ತು ಉತ್ಪನ್ನ API ಗಳನ್ನು ನಡೆಸುತ್ತದೆ; Python AI ಮತ್ತು ಉತ್ಪಾದನಾ ಕೆಲಸವನ್ನು ನಡೆಸುತ್ತದೆ. ಅವುಗಳನ್ನು ಪ್ರತ್ಯೇಕವಾಗಿ ಇಡುವುದರಿಂದ ಪ್ರತಿಯೊಂದೂ ತನ್ನದೇ ಆದ ನಿಯಮಗಳ ಮೇಲೆ ಬೆಳೆಯಲು ಅನುವು ಮಾಡಿಕೊಡುತ್ತದೆ, ಆದರೆ ಕ್ಲೈಂಟ್‌ಗಳು ಹಂಚಿದ ಒಪ್ಪಂದದ ಮೇಲೆ ತೆಳುವಾದ ವೀಕ್ಷಣೆಗಳಾಗಿ ಉಳಿಯುತ್ತವೆ. ಅಪ್ಲಿಕೇಶನ್‌ಗಳಿಗಾಗಿ React Native, ವೆಬ್‌ಗಾಗಿ Next.js.

**ಸರಿಯಾದ ಪರಿಕರಗಳೊಂದಿಗೆ ವೇಗವಾಗಿ.** ಗುಣಮಟ್ಟವನ್ನು ಕಳೆದುಕೊಳ್ಳದೆ ಇಷ್ಟು ದೊಡ್ಡ ಮೇಲ್ಮೈ ಪ್ರದೇಶದಲ್ಲಿ ವೇಗವಾಗಿ ಚಲಿಸಲು ನಾನು Claude Code ಅನ್ನು ಅವಲಂಬಿಸುತ್ತೇನೆ, ಇದು ಆರಂಭಿಕ ಹಂತದ ಉತ್ಪನ್ನವು ಬೇಡುವ ವೇಗದಲ್ಲಿ ಅಪ್ಲಿಕೇಶನ್, ವೆಬ್ ಮತ್ತು ಎರಡೂ ಬ್ಯಾಕೆಂಡ್‌ಗಳಲ್ಲಿ ಕೆಲಸವನ್ನು ನಿರ್ವಹಿಸಲು ನನಗೆ ಅನುವು ಮಾಡಿಕೊಡುತ್ತದೆ.

## ನಿರ್ಧಾರಗಳು

**ಒಂದು ಉತ್ಪನ್ನದ ಮೆದುಳು, ಅನೇಕ ಮೇಲ್ಮೈಗಳು.** ಅಪ್ಲಿಕೇಶನ್‌ಗಳು, ವೆಬ್ ಮತ್ತು ಬ್ಯಾಕೆಂಡ್ ಅನ್ನು ಒಂದೇ ಸಣ್ಣ ತಂಡವು ಹೊಂದಿರುವಾಗ, ಅಗ್ಗದ ಆರ್ಕಿಟೆಕ್ಚರ್ ಎಂದರೆ ಪ್ರತಿ ಕ್ಲೈಂಟ್ ಅನ್ನು ತೆಳುವಾದ ವೀಕ್ಷಣೆಯಾಗಿ ಪರಿಗಣಿಸುವ ಹಂಚಿದ API ಪದರ. ವೈಶಿಷ್ಟ್ಯಗಳು ಒಮ್ಮೆ ಇಳಿಯುತ್ತವೆ, ಎಲ್ಲೆಡೆ ರವಾನೆಯಾಗುತ್ತವೆ. ಇದರ ವಿನಿಮಯವೆಂದರೆ ಪ್ಲಾಟ್‌ಫಾರ್ಮ್-ನಿರ್ದಿಷ್ಟ ಪಾಲಿಶ್‌ಗೆ ಉದ್ದೇಶಪೂರ್ವಕ ಬಜೆಟ್ ಬೇಕು; ಬಳಕೆದಾರರು ನಿಜವಾಗಿಯೂ ಅದನ್ನು ಅನುಭವಿಸುವಲ್ಲಿ (ಸನ್ನೆ ಪ್ರತಿಕ್ರಿಯೆ, ಚಿತ್ರ ಲೋಡಿಂಗ್) ನಾವು ಅದನ್ನು ಖರ್ಚು ಮಾಡಿದ್ದೇವೆ ಮತ್ತು ಅವರು ಅನುಭವಿಸದ ಕಡೆ ಅದನ್ನು ಬಿಟ್ಟುಬಿಟ್ಟಿದ್ದೇವೆ.

**AI ತನ್ನ ಮೌಲ್ಯವನ್ನು ಗಳಿಸುವಲ್ಲಿ ಅದನ್ನು ರವಾನಿಸಿ.** LLM ಕರೆಗಳು ಸ್ಟಾಕ್‌ನಲ್ಲಿರುವ ಎಲ್ಲದಕ್ಕೂ ಹೋಲಿಸಿದರೆ ನಿಧಾನ ಮತ್ತು ದುಬಾರಿಯಾಗಿದೆ. ಉದ್ದೇಶ ಸೆರೆಹಿಡಿಯುವಿಕೆ ಮತ್ತು ಉಡುಪು ಸಂಪಾದನೆಗಾಗಿ ಸಂಭಾಷಣಾ ಪದರವನ್ನು ನಾವು ಉಳಿಸಿಕೊಂಡಿದ್ದೇವೆ, ಬಳಕೆದಾರರು ಇಷ್ಟಪಡುವ ಭಾಗ, ಮತ್ತು ಪೂರ್ವಭಾವಿಯಾಗಿ ಲೆಕ್ಕಹಾಕಬಹುದಾದ ಎಲ್ಲವನ್ನೂ ಹಿನ್ನೆಲೆ ಕೆಲಸಗಳಿಗೆ ಸರಿಸಿದ್ದೇವೆ. ಅಪ್ಲಿಕೇಶನ್ AI ನಂತೆ ಭಾಸವಾಗುತ್ತದೆ; ಲೇಟೆನ್ಸಿ ಬಜೆಟ್ ಸಾಮಾನ್ಯ ಇ-ಕಾಮರ್ಸ್ ಅಪ್ಲಿಕೇಶನ್‌ನಂತೆ ಓದುತ್ತದೆ.

**ಉತ್ಪಾದನೆಯಲ್ಲಿ ಪ್ರಾಮಾಣಿಕವಾಗಿ ಪುನರಾವರ್ತಿಸಿ.** ಆರಂಭಿಕ ಹಂತದ ಉತ್ಪನ್ನಗಳು ಆರು ತಿಂಗಳ ರೋಡ್‌ಮ್ಯಾಪ್‌ಗಳಲ್ಲಿ ಉಳಿಯುವುದಿಲ್ಲ. ನಾವು ಸಣ್ಣದಾಗಿ ರವಾನಿಸಿದ್ದೇವೆ, ನಿಜವಾದ ನಡವಳಿಕೆಯನ್ನು ವೀಕ್ಷಿಸಿದ್ದೇವೆ ಮತ್ತು ನಾವು ಇಷ್ಟಪಟ್ಟ ವೈಶಿಷ್ಟ್ಯಗಳನ್ನು ಒಳಗೊಂಡಂತೆ ಬಳಕೆಯನ್ನು ಹೆಚ್ಚಿಸದ ವೈಶಿಷ್ಟ್ಯಗಳನ್ನು ನಿಲ್ಲಿಸಿದ್ದೇವೆ.
